# Guía y Scripts de Implementación: Configuración de un Entorno de Desarrollo de Aplicaciones en GCP

Este documento recopila todos los comandos necesarios para resolver paso a paso el laboratorio práctico en **Google Cloud Shell**. Cada sección incluye una explicación detallada del propósito de cada instrucción seguida de su respectivo bloque de código listo para ejecutar.

---

## Tarea 1: Crea un bucket en Cloud Storage

### ¿Qué hace este código?
* **`gcloud storage buckets create`**: Invoca la herramienta de línea de comandos de Google Cloud Storage para crear un nuevo depósito (bucket) de almacenamiento de objetos.
* **`gs://qwiklabs-gcp-01-c99c5af329ef-bucket`**: Define el identificador único global del bucket. El prefijo `gs://` es obligatorio para indicar que se trata de un recurso de Cloud Storage.
* **`--location=us-west1`**: Establece la ubicación geográfica del bucket en la región `us-west1`. Los buckets son recursos regionales o multirregionales, por lo que no se especifica una zona puntual.

### Bloque de código
```bash
gcloud storage buckets create gs://qwiklabs-gcp-01-c99c5af329ef-bucket --location=us-west1
```

---

## Tarea 2: Crea un tema de Pub/Sub

### ¿Qué hace este código?
* **`gcloud pubsub topics create`**: Crea un nuevo canal de mensajería asíncrona (tema o *topic*) en el servicio Cloud Pub/Sub.
* **`topic-memories-150`**: Asigna el nombre exacto al tema donde la función de Cloud Run publicará una notificación cada vez que procese exitosamente una miniatura. Al ser un recurso global, no requiere especificar una región.

### Bloque de código
```bash
gcloud pubsub topics create topic-memories-150
```

## Tarea 3: Crea la función de Cloud Run de la miniatura

Esta tarea se divide en siete pasos secuenciales para preparar el entorno, gestionar los permisos de seguridad (IAM), desplegar la función en segunda generación y validar su funcionamiento.

### Paso 1: Crear el directorio de trabajo y los archivos fuente (`package.json` e `index.js`)

#### ¿Qué hace este código?
* **`mkdir -p memories-function && cd memories-function`**: Crea una carpeta dedicada para el proyecto y accede a ella para mantener los archivos aislados.
* **`cat << 'EOF' > package.json`**: Genera el archivo de manifiesto de Node.js declarando las dependencias requeridas: `@google-cloud/functions-framework` (entorno de ejecución), `@google-cloud/pubsub` (mensajería), `@google-cloud/storage` (lectura/escritura de archivos) y `sharp` (procesamiento y redimensionamiento de imágenes).
* **`cat << 'EOF' > index.js`**: Crea el código principal de la función `memories-thumbnail-generator`. Este script escucha eventos de creación de objetos en el bucket, verifica que el archivo no sea ya una miniatura (`64x64_thumbnail`) y valida que tenga extensión `.png`, `.jpg` o `.jpeg`. Si cumple las condiciones, descarga la imagen, la redimensiona a `64x64` píxeles manteniendo la proporción (`fit: 'inside'`), la guarda nuevamente en el bucket con el sufijo `_64x64_thumbnail` y publica el nombre del nuevo archivo en el tema `topic-memories-150`.

#### Bloque de código
```bash
# 1. Crear o entrar al directorio de trabajo
mkdir -p memories-function && cd memories-function

# 2. Crear el archivo package.json con las versiones exactas solicitadas
cat << 'EOF' > package.json
{
 "name": "thumbnails",
 "version": "1.0.0",
 "description": "Create Thumbnail of uploaded image",
 "scripts": {
   "start": "node index.js"
 },
 "dependencies": {
   "@google-cloud/functions-framework": "^3.0.0",
   "@google-cloud/pubsub": "^2.0.0",
   "@google-cloud/storage": "^6.11.0",
   "sharp": "^0.32.1"
 },
 "devDependencies": {},
 "engines": {
   "node": ">=4.3.2"

}
EOF

# 3. Crear el archivo index.js con la lógica de procesamiento
cat << 'EOF' > index.js
const functions = require('@google-cloud/functions-framework');
const { Storage } = require('@google-cloud/storage');
const { PubSub } = require('@google-cloud/pubsub');
const sharp = require('sharp');

functions.cloudEvent('memories-thumbnail-generator', async cloudEvent => {
 const event = cloudEvent.data;

 console.log(`Event: ${JSON.stringify(event)}`);
 console.log(`Hello ${event.bucket}`);

 const fileName = event.name;
 const bucketName = event.bucket;
 const size = "64x64";
 const bucket = new Storage().bucket(bucketName);
 const topicName = "topic-memories-150";
 const pubsub = new PubSub();

 if (fileName.search("64x64_thumbnail") === -1) {
 // no tiene una miniatura, obtener extensión de archivo de nombre
 const filename_split = fileName.split('.');
 const filename_ext = filename_split[filename_split.length - 1].toLowerCase();
 const filename_without_ext = fileName.substring(0, fileName.length - filename_ext.length - 1); // corregir subcadena para quitar el punto

 if (filename_ext === 'png' || filename_ext === 'jpg' || filename_ext === 'jpeg') {
 // solo admite png y jpg en este punto
 console.log(`Processing Original: gs://${bucketName}/${fileName}`);
 const gcsObject = bucket.file(fileName);
 const newFilename = `${filename_without_ext}_64x64_thumbnail.${filename_ext}`;
 const gcsNewObject = bucket.file(newFilename);

 try {
 const [buffer] = await gcsObject.download();
 const resizedBuffer = await sharp(buffer)
 .resize(64, 64, {
 fit: 'inside',
 withoutEnlargement: true,
 })
 .toFormat(filename_ext)
 .toBuffer();

 await gcsNewObject.save(resizedBuffer, {
 metadata: {
 contentType: `image/${filename_ext}`,
 },
 });

 console.log(`Success: ${fileName} → ${newFilename}`);

 await pubsub
 .topic(topicName)
 .publishMessage({ data: Buffer.from(newFilename) });

 console.log(`Message published to ${topicName}`);
 } catch (err) {
 console.error(`Error: ${err}`);
 }
 } else {
 console.log(`gs://${bucketName}/${fileName} is not an image I can handle`);
 }
 } else {
 console.log(`gs://${bucketName}/${fileName} already has a thumbnail`);
 }
});
EOF
```

### Paso 2: Habilitar las APIs necesarias

#### ¿Qué hace este código?
* **`gcloud services enable`**: Activa los servicios de Google Cloud indispensables para compilar, contenerizar, enrutar eventos y ejecutar funciones de segunda generación (`Artifact Registry`, `Cloud Functions`, `Cloud Build`, `Eventarc`, `Cloud Run`, `Cloud Logging` y `Cloud Pub/Sub`).

#### Bloque de código
```bash
gcloud services enable   artifactregistry.googleapis.com   cloudfunctions.googleapis.com   cloudbuild.googleapis.com   eventarc.googleapis.com   run.googleapis.com   logging.googleapis.com   pubsub.googleapis.com
```

### Paso 3: Configurar permisos IAM requeridos para Eventarc y Storage

#### ¿Qué hace este código?
* **Obtención de identificadores (`PROJECT_ID`, `PROJECT_NUMBER`, `SERVICE_ACCOUNT`)**: Consulta dinámicamente el ID del proyecto activo, su número de proyecto y el agente de servicio interno de Cloud Storage.
* **`roles/pubsub.publisher`**: Permite que Cloud Storage publique notificaciones en Pub/Sub cuando se sube un archivo nuevo al bucket.
* **`roles/eventarc.eventReceiver` y `roles/run.invoker`**: Autoriza a la cuenta de servicio predeterminada de Compute Engine para recibir eventos de Eventarc e invocar el servicio subyacente de Cloud Run.
* **`roles/eventarc.serviceAgent`**: Otorga al agente de Eventarc los permisos necesarios para gestionar los activadores de eventos.
* **`--condition=None` y `sleep 15`**: Evita bloqueos interactivos en proyectos con políticas IAM condicionales y espera 15 segundos para asegurar la propagación de los permisos antes del despliegue.

#### Bloque de código
```bash
PROJECT_ID=$(gcloud config get-value project)
PROJECT_NUMBER=$(gcloud projects describe $PROJECT_ID --format='value(projectNumber)')
SERVICE_ACCOUNT=$(gsutil kms serviceaccount -p $PROJECT_ID)

gcloud projects add-iam-policy-binding $PROJECT_ID   --member="serviceAccount:${SERVICE_ACCOUNT}"   --role="roles/pubsub.publisher"   --condition=None

gcloud projects add-iam-policy-binding $PROJECT_ID   --member="serviceAccount:${PROJECT_NUMBER}-compute@developer.gserviceaccount.com"   --role="roles/eventarc.eventReceiver"   --condition=None

gcloud projects add-iam-policy-binding $PROJECT_ID   --member="serviceAccount:${PROJECT_NUMBER}-compute@developer.gserviceaccount.com"   --role="roles/run.invoker"   --condition=None

gcloud projects add-iam-policy-binding $PROJECT_ID   --member="serviceAccount:service-${PROJECT_NUMBER}@gcp-sa-eventarc.iam.gserviceaccount.com"   --role="roles/eventarc.serviceAgent"   --condition=None

sleep 15
```

### Paso 4: Desplegar la función de Cloud Run (2ª generación)

#### ¿Qué hace este código?
* **`gcloud functions deploy memories-thumbnail-generator`**: Compila el código fuente del directorio actual (`.`) y lo despliega como una función de Cloud Run.
* **`--gen2` y `--runtime=nodejs22`**: Configura el entorno de ejecución de **2ª generación** utilizando **Node.js 22**.
* **`--region=us-west1`**: Ubica la función en la misma región que el bucket de almacenamiento para reducir latencia y evitar errores de activadores entre regiones.
* **`--entry-point=memories-thumbnail-generator`**: Indica el nombre exacto de la función exportada en `index.js` que responderá al evento.
* **`--trigger-bucket=qwiklabs-gcp-01-c99c5af329ef-bucket`**: Crea un activador automático de Eventarc que dispara la función cada vez que se finaliza la subida o creación de un archivo en dicho bucket.
* **`--allow-unauthenticated`**: Permite la invocación del endpoint HTTP subyacente sin requerir autenticación adicional externa.

#### Bloque de código
```bash
gcloud functions deploy memories-thumbnail-generator   --gen2   --runtime=nodejs22   --region=us-west1   --source=.   --entry-point=memories-thumbnail-generator   --trigger-bucket=qwiklabs-gcp-01-c99c5af329ef-bucket   --allow-unauthenticated
```

### Paso 5: Subir imagen de prueba y verificar miniatura

#### ¿Qué hace este código?
* **`curl -O ...`**: Descarga localmente en Cloud Shell la imagen de muestra `map.jpg` desde el repositorio público de entrenamiento.
* **`gcloud storage cp`**: Sube `map.jpg` al bucket configurado, lo que dispara automáticamente la ejecución de la función `memories-thumbnail-generator`.
* **`sleep 10` y `gcloud storage ls`**: Espera 10 segundos a que finalice el procesamiento en segundo plano y lista los objetos del bucket para comprobar que existe tanto el archivo original (`map.jpg`) como su versión reducida (`map_64x64_thumbnail.jpg`).

#### Bloque de código
```bash
curl -O https://storage.googleapis.com/cloud-training/gsp315/map.jpg
gcloud storage cp map.jpg gs://qwiklabs-gcp-01-c99c5af329ef-bucket/
sleep 10
gcloud storage ls gs://qwiklabs-gcp-01-c99c5af329ef-bucket/
```

## Tarea 4: Quita al anterior ingeniero de servicios de nube

### ¿Qué hace este código?
* **`PROJECT_ID=$(gcloud config get-value project)`**: Obtiene el identificador del proyecto actual de Google Cloud.
* **`gcloud projects remove-iam-policy-binding`**: Revoca los permisos de acceso a nivel de proyecto.
* **`--member="user:student-02-a1ed28658c03@qwiklabs.net"`**: Especifica la cuenta de correo del ingeniero anterior que debe perder el acceso.
* **`--role="roles/viewer"`**: Indica el rol de Visualizador que se le va a retirar.
* **`--all`**: Elimina todas las vinculaciones coincidentes (incluyendo posibles políticas condicionales) sin detener la ejecución con preguntas interactivas.

### Bloque de código
```bash
PROJECT_ID=$(gcloud config get-value project)

gcloud projects remove-iam-policy-binding $PROJECT_ID   --member="user:student-02-a1ed28658c03@qwiklabs.net"   --role="roles/viewer"   --all
```
